                                                  ABSTRACT

         Autonomous driving systems require perception methods that understand the entire driving scene rather

than isolated objects alone. Traditional object detection can localize vehicles and pedestrians with bounding boxes,

but it does not show the exact spatial extent of drivable road, sidewalks, buildings, boundaries, obstacles, or

vulnerable road users. This project investigates semantic segmentation as a pixel-level perception technique for

urban driving scenes. The work focuses on FRRN-A, a Full-Resolution Residual Network architecture designed to

preserve spatial detail while also learning deep contextual information. Using a Cityscapes/Darmstadt-style urban

driving subset, the project adapts legacy TensorFlow segmentation code, resolves compatibility issues in a current

Paperspace GPU environment, trains the model for 100 epochs, saves checkpoints, and generates prediction masks

for qualitative evaluation. The report presents the motivation for pixel-level understanding, background on

segmentation models, dataset preparation, FRRN-A architecture, implementation decisions, evaluation observations,

and future work. The evaluation combines training-loss analysis, checkpoint verification, prediction-mask

inspection, and a limited proxy foreground/background alignment analysis on visualized validation examples. The

results show that the implementation successfully produces meaningful segmentation masks for large scene regions

and road-user groups, while also revealing limitations around small objects, distant pedestrians, boundary detail, and

the absence of full benchmark metrics such as mean intersection-over-union. Overall, the project demonstrates a

complete engineering pipeline for adapting and training an FRRN-A semantic segmentation model for autonomous

driving scene understanding, and it identifies clear steps toward more rigorous quantitative validation and real-time

road-video deployment.

                                             INTRODUCTION

1.1 Project Context

         Autonomous vehicles depend on perception systems that can transform camera streams and sensor

information into structured scene understanding. A driving scene contains multiple kinds of information: the

drivable road surface, sidewalks, lanes, vehicles, pedestrians, traffic signs, buildings, sky, background objects, and

temporary obstacles. A safe driving system must recognize these elements and understand their spatial relationships.

In many introductory computer vision systems, the perception task is framed as classification or object detection.

Classification assigns a single label to an image, while object detection finds rectangular boxes around important

objects. These tasks are useful, but they are not sufficient for all driving decisions because the exact boundary

between road and non-road regions can matter as much as the presence of an object.

         Semantic segmentation addresses this limitation by assigning a class label to every pixel in an image.

Instead of saying only that an image contains a car or drawing a bounding box around a pedestrian, semantic

segmentation can mark which pixels correspond to road, vehicle, pedestrian, sidewalk, sky, building, or other scene

classes. This dense prediction approach is especially relevant to autonomous driving, where a vehicle must reason

about spatial boundaries and the usable road surface. A segmentation mask can be treated as a scene map that is

more detailed than a collection of object boxes.

         My project, titled Teaching Autonomous Vehicles to See the Road: Pixel-Level Scene Understanding with

FRRN-A, explores semantic segmentation for autonomous driving perception. The technical focus is FRRN-A, a

Full-Resolution Residual Network designed to preserve full-resolution spatial details while still learning deep

contextual information. The project adapts and trains an FRRN-A implementation on a Cityscapes/Darmstadt-style

urban driving subset, generates model checkpoints, and produces prediction masks for analysis.


1.2 Research Problem

         The central problem addressed in this project is the gap between object-level perception and pixel-level

driving-scene understanding. Object detection is useful for identifying that a pedestrian or vehicle exists, but it does

not indicate the precise boundary of the object or the exact shape of the drivable road. For a vehicle operating in a

                        MOTIVATION AND SIGNIFICANCE

2.1 Why Pixel-Level Understanding Matters

         A self-driving car must understand not only what objects exist, but also where they occupy space in relation

to the road. A bounding box around a pedestrian can be helpful, yet it includes background pixels and does not show

the exact shape of the pedestrian. A box around a car may not distinguish the vehicle body from the road behind it.

A road region cannot be described accurately by one rectangle because roads curve, lanes narrow, sidewalks

intersect, and obstacles appear along boundaries.

         Pixel-level semantic segmentation directly addresses these issues. In a segmentation mask, every pixel

receives a predicted class. For road-scene understanding, this means that the output can represent drivable road,

sidewalks, vehicles, pedestrians, building surfaces, sky, vegetation, and other background regions. This dense scene

representation can support downstream modules that need more detail than object boxes provide.

         The motivation is especially strong in safety-critical scenarios. If a vehicle misinterprets the edge of a

sidewalk, misses a narrow pedestrian region, or fails to distinguish road from background, the planning system can

be affected. Pixel-level segmentation is not required for every decision, but it provides valuable structure when

boundaries matter. The tradeoff is that segmentation is computationally heavier than classification or object

detection, which is why model design and input resolution are important.

learning perception systems are built beyond high-level demonstrations. A common misconception is that deep

learning projects are mainly about choosing a model and running a training command. In practice, much of the work

involves dataset organization, environment configuration, legacy-code adaptation, dependency management, GPU

memory constraints, checkpoint handling, and result interpretation.

                        RELATED WORK AND TECHNIQUES

3.1 Semantic Segmentation Background

         Semantic segmentation has been a major computer vision task for scene understanding. The goal is to

predict a class label for each pixel in an image. Unlike classification, semantic segmentation requires the model to

preserve spatial structure. Unlike object detection, semantic segmentation does not stop at rectangular object

locations. It produces a dense prediction map with the same spatial structure as the input image.

         Fully Convolutional Networks introduced the idea of adapting classification networks into dense prediction

systems by replacing fully connected layers with convolutional operations and using upsampling to return

predictions to image resolution (Long, Shelhamer, & Darrell, 2015). This idea influenced many segmentation

architectures. Encoder-decoder networks such as U-Net and SegNet became important because they compress

spatial information and then recover resolution through decoding or upsampling stages (Ronneberger, Fischer, &

Brox, 2015; Badrinarayanan, Kendall, & Cipolla, 2017).

         Modern segmentation architectures often balance local detail and global context. Local detail is required for

boundaries and small objects. Global context is required to understand larger scene structure. Autonomous driving

segmentation needs both because road surfaces are large continuous regions while pedestrians and traffic objects can

be small and sparse.


3.2 Residual Learning

         Residual learning was introduced to make deep neural networks easier to train. Instead of forcing a network

block to learn an entire transformation directly, a residual block learns a residual update and adds it to the input

representation. This helps gradients flow through deep networks and reduces degradation problems in very deep

architectures (He, Zhang, Ren, & Sun, 2016).

         Residual connections are relevant to FRRN-A because the architecture uses residual units and full-

resolution residual units. The intent is to preserve useful information while allowing the network to learn deeper

features. In segmentation, residual connections can support training stability when the model must combine low-

level spatial details with high-level context.

3.3 Full-Resolution Residual Networks

         Full-Resolution Residual Networks were proposed for semantic segmentation in street scenes. The key

design choice is maintaining a full-resolution stream throughout the network while also using a pooling stream that

learns contextual features at lower spatial resolutions (Pohlen et al., 2017). This design is different from a simple

encoder-decoder model that compresses the input and later reconstructs an output. FRRN maintains a stream that

preserves fine spatial information, which can be useful for boundaries and dense pixel prediction.

         FRRN-A is a smaller version of the FRRN family. In this project, FRRN-A was chosen because it offers a

meaningful architecture for road-scene segmentation while remaining feasible for a course-scale implementation on

available GPU resources. The architecture includes initial convolution layers, residual units, downsampling stages,

full-resolution residual blocks, upsampling stages, feature fusion, and final pixel-wise prediction.


3.4 Cityscapes and Urban Scene Understanding

         The Cityscapes dataset is a widely used benchmark for urban street-scene understanding. It provides

images from cities with pixel-level semantic annotations for road, sidewalk, building, vegetation, vehicles, persons,

and other classes (Cordts et al., 2016). The Darmstadt subset used in this project provides urban driving scenes

suitable for training and evaluation examples. Cityscapes-style data is relevant because it resembles the types of

environments autonomous vehicles must interpret.

         In this project, the available Darmstadt data was used as a course-scale subset rather than as a full official

benchmark split. This matters for interpretation. Results should be understood as evidence that the implementation

works and produces meaningful masks, not as official Cityscapes benchmark scores.

connections and strong performance in data-limited segmentation tasks. SegNet uses an encoder-decoder structure

and pooling indices for upsampling. DeepLab models use atrous convolution and spatial pyramid pooling to capture

multi-scale context (Chen et al., 2018). FRRN-A differs by explicitly maintaining a full-resolution residual stream

5.4 FRRN-A Architecture

         FRRN-A is the central technical model used in my project. FRRN-A stands for Full-Resolution Residual

Network-A, and its purpose is to support dense semantic segmentation while preserving spatial detail. This is

important in autonomous driving because the model must identify not only what objects exist in a scene, but also

where their boundaries occur at the pixel level.

         The architecture can be understood as a two-stream network. The full-resolution stream preserves high-

resolution spatial information throughout the model, while the pooling stream learns deeper contextual features

through downsampling. This design helps the model combine fine local boundaries with broader scene context,

which is useful for understanding road regions, vehicles, pedestrians, sidewalks, buildings, sky, and background.

         The implementation begins with an initial convolution stage followed by local residual units. A residual

unit applies convolutional transformations, batch normalization, and nonlinear activation while supporting stable

information flow through residual learning. Residual connections are useful because they reduce the difficulty of

training deeper networks and help preserve information that might otherwise be weakened through many

convolutional layers.

         The full-resolution residual unit is the most distinctive part of FRRN-A. In this unit, information from the

pooling stream is combined with a downsampled form of the full-resolution stream. The combined representation is

processed by convolutional layers, and then a 1 x 1 convolution and upsampling step project information back into

the full-resolution stream. This allows the network to learn semantic meaning while still retaining location-sensitive

boundary information.

         The downsampling path increases the receptive field so the network can recognize larger scene context,

such as road layout and building-background structure. The upsampling path restores spatial resolution and prepares

the network for pixel-wise classification. The final output is a segmentation map with shape H x W x C, where H

and W represent the output height and width and C represents the number of scene classes predicted for each pixel.

         This model selection fits the goal of the project because the project is not limited to recognizing that a

vehicle or pedestrian is present. The goal is to produce a pixel-level interpretation of the driving scene. In that sense,

FRRN-A is technically different from a simple classification model or a bounding-box detector. It produces a dense

scene mask that can represent road surfaces, object regions, and other urban-driving components in a spatially

detailed way.

         My implementation work focused on making this architecture run successfully in the available

environment. I adapted the TensorFlow-based FRRN-A code, resolved compatibility issues, trained the network for

100 epochs, saved checkpoints, and generated prediction masks from validation images. This makes the technical

contribution both architectural and practical: the report documents how the FRRN-A design was used and how the

legacy implementation was made executable for the final project.

5.6 Why 100 Epochs Were Used

         The choice of 100 epochs was a practical experimental decision. Fewer epochs would not provide enough

training history to observe the learning behavior of FRRN-A, while much longer training could increase the risk of

overfitting the small subset and require more GPU time. With 100 epochs, the model had enough opportunity to

learn visible segmentation structure, save checkpoints, and generate prediction masks, while remaining feasible in

the available environment.

                        CONCLUSION AND FUTURE WORK

7.1 Conclusion

         In this project, I demonstrated a complete semantic segmentation workflow for autonomous driving scene

understanding using FRRN-A. The project began with the motivation that self-driving vehicles need more than

bounding boxes. They need pixel-level information about drivable road, vehicles, pedestrians, sidewalks, buildings,

sky, and background. Semantic segmentation provides that dense scene representation.

         I successfully adapted a legacy TensorFlow FRRN-A implementation, resolved compatibility issues,

trained the model for 100 epochs, saved checkpoints, and generated prediction masks. The results show that the

model learned meaningful urban scene structure, especially large regions and visible road-user groups. The work

also identified limitations in small-object detection, boundary precision, and missing formal metrics.

         The strongest contribution of my work is the full implementation pipeline. The project required dataset

organization, environment setup, legacy-code adaptation, GPU training, checkpoint management, prediction

generation, qualitative evaluation, and reproducibility documentation through GitHub and a project demo recording.

These activities demonstrate a realistic machine learning engineering workflow.


7.2 Future Work

         Future work should address the evaluation gap and improve model robustness. The most important next

step is a formal metric pipeline that calculates pixel accuracy, mean intersection-over-union, and per-class IoU on a

standardized validation split. This would allow direct comparison with U-Net, FCN, SegNet, DeepLab, and newer

transformer-based segmentation models.

         Train on a larger and more diverse Cityscapes split to improve generalization.

         Implement official quantitative metrics: pixel accuracy, mean IoU, per-class IoU, precision, and recall.

         Compare FRRN-A against baselines such as U-Net, FCN, SegNet, and DeepLab under the same dataset

split.

         Use data augmentation, class weighting, and boundary-aware losses to improve small-object and edge

segmentation.

        APPENDIX E. QUANTITATIVE EVALUATION NOTES

         This appendix explains how the limited proxy quantitative analysis in Chapter 6 was produced and how

future official metrics should be implemented. It is included to make the evaluation transparent rather than to

overclaim benchmark performance.

         For the proxy analysis, each visual comparison figure was divided into the ground-truth panel and the

prediction panel. The dominant color in each panel was treated as background. All other colors were treated as

foreground. This produced binary masks for foreground/background comparison. The proxy foreground IoU was

calculated as the intersection of foreground pixels divided by the union of foreground pixels. Binary pixel agreement

was calculated as the percentage of pixels where the collapsed foreground/background labels matched.

         # Conceptual proxy metric pseudocode

         load comparison image

         crop ground_truth_panel and prediction_panel

         remove title/header region

         for each panel:

            find dominant RGB color

            background = pixels close to dominant color

            foreground = all other pixels

         proxy_iou = foreground_intersection / foreground_union

         binary_agreement = matching_foreground_background_pixels / total_pixels

         The proxy metric was useful because the reporting pipeline saved colorized masks rather than official label-

ID tensors for every validation image. It gives a simple numerical check of broad region alignment in the visual

examples. It should not be reported as official semantic segmentation accuracy.

         For future work, the prediction script should save raw integer label maps in addition to colorized images.

The evaluation script should then compare predicted label IDs with ground-truth label IDs using the same class

mapping. This would make it possible to calculate pixel accuracy, mean IoU, per-class IoU, frequency-weighted

IoU, precision, and recall on the validation set.
